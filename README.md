# map-data

The **data layer** of the gpui fork map: the deterministic export the
[`map`](https://github.com/gpui-archipelago/map) viewer renders. Nothing here
is hand-edited — `data/` is regenerated by CI from the measured gpui contract
dataset and committed as the artifact the site serves.

## What produces it

The generator is the **published** [`cargo-gocar`](https://crates.io/crates/cargo-gocar)
CLI. It is deliberately data-agnostic: the tool carries no gpui data, and
resolves both its dataset and its curated inputs at runtime from the public
[`gpui-corpus`](https://github.com/gpui-archipelago/gpui-corpus) repo:

| Input | Source |
| --- | --- |
| measured dataset (`gpui-contract.json.xz`, `gocar.contract.v0`) | `gpui-corpus` @ `measured` |
| curation (`curation/*.json`: migration rules, companions, compile markers, kit probes, upstream sources, binding notes) | `gpui-corpus` @ `main` |

`.github/workflows/export.yml` runs, on a weekly schedule and on manual
dispatch:

```bash
cargo install cargo-gocar --version "$GOCAR_VERSION" --locked
cargo-gocar \
  --dataset corpus-measured/gpui-contract.json.xz \
  --curation corpus-main/curation \
  export-fork-map --out data/forkmap.json
```

then commits the changed files under `data/`.

## The data family

One export emits the whole `gocar.forkmap.*` family — a boot manifest plus
lazily-fetched sidecars and bucket files (the site never loads the full
corpus on its boot path):

| File | Schema | What it is |
| --- | --- | --- |
| `forkmap.json` | `gocar.forkmap.v1` | the full corpus bundle: provider rows + measured item surfaces, rules, scaffold templates, kit probes |
| `forkmap-manifest.json` | `gocar.forkmap.manifest.v1` | the boot payload: the bundle minus every measured surface, plus export-precomputed corpus counts |
| `forkmap-fn-texts.json` | `gocar.forkmap.fntexts.v1` | per-version effective canonical `fn:` signature texts |
| `forkmap-doc-texts.json` | `gocar.forkmap.doctexts.v1` | per-version effective `fn:` doc-comment text |
| `forkmap-source-locs.json` | `gocar.forkmap.srclocs.v1` | measured declaration source locations |
| `forkmap-type-members.json` | `gocar.forkmap.typemembers.v2` | consumer-visible member segments, content-addressed by digest |
| `forkmap-alignment.json` | `gocar.forkmap.alignment.v1` | the Alignment digest-state tables (canonical column store) |
| `forkmap-align-index.json` | `gocar.forkmap.alignindex.v1` | the type-ahead index (resident Alignment payload) |
| `forkmap-column-###.json` | `gocar.forkmap.column.v1` | per-key column fragments (fetched per selected item) |
| `forkmap-payload-###.json` | `gocar.forkmap.payload.v1` | per-key payload fragments (fn texts, docs, locations) |
| `forkmap-release-###.json` | `gocar.forkmap.release.v1` | per-release surface rows for a two-release diff |
| `forkmap-journal.json` | `gocar.forkmap.journal.v1` | the Journal feed's precomputed story lines |

The export is **deterministic**: a no-change re-run is byte-identical (the
"data as of" line is the dataset's own `synced_at`, never wall-clock), so the
workflow commits only when the data actually moved.

## Consuming it

Public, unauthenticated, at
`https://raw.githubusercontent.com/gpui-archipelago/map-data/main/data/`.

The viewer is co-versioned with the exporter by the `GOCAR_VERSION` pin in
`.github/workflows/export.yml`: the schemas are validated strictly at load, so
a data/viewer skew is a hard failure, not a silently misread page. Bump the
pin and the viewer together.

## Running the export yourself

The export is one command; `map`'s own docs cover the viewer. For a local
regeneration, clone `gpui-corpus` at both refs (or fetch its store), then run
the command above against the tool version in `GOCAR_VERSION`.
